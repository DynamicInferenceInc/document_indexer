Выдели два поля.

1) functional_direction — из роли на проекте, иначе из выполненных работ, иначе из должности в шапке. Нужен блок, модуль или предметная область (Казначейство, Финансы, MM, Бухгалтерский учет), а не грейд (консультант, архитектор, руководитель). Не копируй роль целиком.

2) solution_platform — на какой базе сделано решение: только «1С» или «SAP». Смотри роль, описание проекта и выполненные работы. Если переход с одной базы на другую — бери целевую («переход с SAP R/3 на 1С:ERP» → 1С). Если нельзя уверенно выбрать — null.

Верни только JSON по схеме. Не выдумывай.

Примеры направления:
- «Консультант по направлению Казначейство» → Казначейство
- «Архитектор по блоку Финансы (Бухгалтерский и налоговый учет, …)» → Финансы
- «Функциональный консультант SAP MM» → SAP MM
- роль пустая, в работах «настройка казначейства и банковских выписок» → Казначейство
- роль «Разработчик», должность в шапке «Консультант 1С:ЗУП» → 1С:ЗУП

Примеры базы:
- «Внедрение 1С:ERP» → 1С
- «Функциональный консультант SAP MM» → SAP
- «переход с SAP R/3 на 1C ERP» → 1С
